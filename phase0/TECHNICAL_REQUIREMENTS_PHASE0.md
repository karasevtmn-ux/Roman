# Техническое задание (Фаза 0, перезапуск)
## Система мониторинга карточек дел ГАС «Правосудие» — Windows Desktop

**Версия:** 0.2 (черновик на согласование)  
**Дата:** 2026-02-21  
**Статус:** на согласовании с заказчиком

---

## 1. Цель документа
Зафиксировать требования к **desktop-версии для Windows** (без обязательного домена и веб-хостинга), чтобы перейти к разработке Фазы 1.

---

## 2. Формат решения

### 2.1. Базовый формат MVP
- Локальное приложение для Windows (Desktop).
- Работа через графический интерфейс (не через командную строку).
- Один пользователь на одном ПК (без учетных записей).

### 2.2. Причина выбора
- Нет расходов на домен и SSL.
- Быстрый запуск MVP с минимальной инфраструктурой.

### 2.3. Ограничение
- Пользователю нужно установить приложение на ПК.

---

## 3. Цели системы
Пользователь добавляет ссылки на карточки дел, а приложение автоматически ночью проверяет изменения и отправляет email-уведомления.

---

## 4. Функциональные требования MVP

### 4.1. Доступ
1. Приложение работает в однопользовательском режиме.
2. Экран логина/пароля отсутствует.
3. Все ссылки и события хранятся в одном локальном профиле пользователя Windows.

### 4.2. Работа со ссылками
1. Добавление/редактирование/удаление ссылок на дела.
2. В форме добавления/редактирования обязательны поля: **Истец**, **Ответчик**, **Суд**, **Номер дела**, **Комментарий**, **Субъект РФ**.
3. Поддержка двух типов ссылок:
   - `mos-gorsud.ru`;
   - `*.sudrf.ru`.
4. Хранение статуса ссылки (активна/ошибка/проблемная).

### 4.3. Мониторинг
1. Проверка выполняется ночью по локальному времени суда.
2. Часовой пояс суда определяется автоматически по полю **Субъект РФ** (с возможностью ручной корректировки timezone).
3. Целевое окно MVP: **01:00–05:00** местного времени суда.
4. Частота: 1 раз в сутки на ссылку.
5. Поддержка повторных попыток при временных ошибках.

### 4.4. Типы изменений
Система фиксирует:
1. добавление/удаление/изменение номера дела;
2. изменения во вкладках:
   - «Дело»,
   - «Движение дела»,
   - «Стороны по делу (третьи лица)»;
3. добавление/удаление вкладок карточки;
4. добавление/удаление текстов судебных актов.

Примечание по источникам: для многих судов на `sudrf` текст судебного акта действительно появляется как новая вкладка в карточке дела. Для судов Москвы (`mos-gorsud`) новые вкладки обычно не добавляются: судебные акты публикуются во вкладке **«Документы»**. Соответственно, мониторинг должен учитывать оба сценария: (а) появление новой вкладки, (б) обновление содержимого существующей вкладки «Документы».

### 4.5. Уведомления
1. Email при обнаружении изменений.
2. Если добавлен текст судебного акта — отправлять этот текст в письме.
3. Email при недоступной/невалидной ссылке с просьбой обновить ссылку.
4. Каждое email-уведомление должно содержать прямую ссылку на карточку дела для перехода и проверки изменений на сайте суда.

### 4.6. История
1. Хранение истории проверок.
2. Хранение истории изменений (что изменилось, когда, по какой ссылке).

## 5. UX/UI-требования (для следующих итераций)
Этот блок обязателен и входит в план работ.

### 5.1. UX/UI этапы
1. User flow (основные сценарии работы).
2. Wireframes ключевых окон.
3. UI-kit (компоненты и состояния).
4. High-fidelity макеты и дизайн-ревью перед реализацией.

### 5.2. Экранный состав MVP
1. Дашборд/список ссылок с колонками: ссылка, Истец, Ответчик, Суд, Номер дела, Комментарий, статус.
2. Форма добавления/редактирования ссылки.
3. Окно истории изменений.
4. Окно настроек SMTP.
5. Окно настроек расписания проверок.

### 5.3. UX-критерии приемки
1. Добавление ссылки — не более 1 минуты у нового пользователя.
2. Ошибка в ссылке понятна без технических терминов.
3. История изменений читаема и фильтруется по дате.

---

## 6. Нефункциональные требования
1. Работа на Windows 10/11.
2. Локальная БД и резервное копирование не реже 1 раза в сутки.
3. Безопасное хранение SMTP-секретов (шифрование/защищенное хранилище ОС).
4. Логирование ошибок парсинга и отправки email.
5. Устойчивость к перезапуску приложения (данные не теряются).
6. Для ночных проверок, когда основной ПК выключен, используется отдельный всегда-включенный Windows-ПК/мини-ПК с запущенным фоновым модулем (без домена и без веб-хостинга).

---

## 7. Критерии приемки MVP
1. Добавление ссылок обоих типов и их валидация.
2. Ночная проверка с учетом часового пояса суда.
3. Email о найденных изменениях.
4. Email с текстом судебного акта при его появлении.
5. Email о проблемной ссылке.
6. Просмотр истории изменений в интерфейсе.
